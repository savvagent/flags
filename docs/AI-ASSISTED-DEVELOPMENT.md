# AI-Assisted Development with Savvagent Flags

This guide explains how to use AI coding assistants (Claude Code, Cursor, GitHub Copilot, etc.) to integrate Savvagent Flags feature flags into your projects.

## Overview

Savvagent Flags provides AI-friendly documentation files that help coding assistants understand our SDKs and generate accurate integration code:

| File | Purpose | Size |
|------|---------|------|
| `llms.txt` | Quick reference with links to detailed docs | ~4KB |
| `llms-full.txt` | Complete documentation in one file | ~15KB |

## Using with AI Coding Assistants

### Claude Code

Claude Code can fetch and use these files directly. Simply ask it to integrate Savvagent Flags:

```
Add Savvagent Flags feature flags to my React app.
Reference: https://raw.githubusercontent.com/savvagent/flags/main/llms-full.txt
```

Or for quick lookups:

```
How do I use Savvagent Flags's useFlag hook?
Check https://raw.githubusercontent.com/savvagent/flags/main/llms.txt
```

**Pro tip**: Add Savvagent Flags docs to your project's context by creating a `.claude/settings.json`:

```json
{
  "context": {
    "urls": [
      "https://raw.githubusercontent.com/savvagent/flags/main/llms-full.txt"
    ]
  }
}
```

### Cursor

In Cursor, you can add the documentation to your project's AI context:

1. Open Settings (Cmd/Ctrl + ,)
2. Go to "Features" > "Docs"
3. Add: `https://raw.githubusercontent.com/savvagent/flags/main/llms-full.txt`

Now when you ask Cursor to add feature flags, it will use accurate Savvagent Flags patterns.

**Chat example:**
```
@docs Add a feature flag to control the new checkout flow
```

### GitHub Copilot

Reference the documentation in your prompt:

```
# Context: Using Savvagent Flags SDK from https://github.com/savvagent/flags
# Add feature flag check for 'new-dashboard' feature
```

Or paste relevant sections from `llms-full.txt` into your prompt for more accurate suggestions.

### Windsurf / Codeium

Add to your workspace configuration:

```json
{
  "ai.contextFiles": [
    "https://raw.githubusercontent.com/savvagent/flags/main/llms-full.txt"
  ]
}
```

### Local File Reference

If you've cloned this repository, you can reference the local files:

```
Add Savvagent Flags feature flags using the docs in ./llms-full.txt
```

## What the AI Will Generate

When you reference our documentation, AI assistants will generate code that:

1. **Uses correct imports**: `import { FlagClient } from '@savvagent/flags-sdk'`
2. **Follows our patterns**: Proper initialization, context passing, error handling
3. **Includes best practices**: Caching, telemetry, default values
4. **Handles edge cases**: Loading states, error fallbacks, cleanup

### Example Generated Code (React)

```tsx
// Generated by AI using Savvagent Flags llms-full.txt
import { SavvagentFlagsProvider, useFlag } from '@savvagent/flags-react';

function App() {
  return (
    <SavvagentFlagsProvider
      config={{
        apiKey: process.env.NEXT_PUBLIC_SAVVAGENT_FLAGS_KEY!,  // SDK keys use 'sdk_' prefix
        enableRealtime: true,  // SSE for real-time flag updates
      }}
    >
      <FeatureComponent />
    </SavvagentFlagsProvider>
  );
}

function FeatureComponent() {
  // Always provide user context for consistent rollout behavior
  const { enabled, loading } = useFlag('new-feature', {
    defaultValue: false,  // Graceful degradation fallback
    context: {
      user_id: currentUser.id,  // Required for sticky rollouts
      environment: 'production',
      attributes: { plan: currentUser.plan },
    },
  });

  if (loading) return <Skeleton />;
  return enabled ? <NewFeature /> : <LegacyFeature />;
}
```

## Troubleshooting AI-Generated Code

### Common Issues

**Wrong SDK import path**
- AI might guess `@savvagent/flags-client` instead of `@savvagent/flags-sdk`
- Solution: Reference llms-full.txt which has correct imports

**Missing context in flag evaluation**
- AI might skip userId for sticky rollouts
- Solution: Our docs emphasize context patterns

**No error handling**
- AI might generate optimistic code without fallbacks
- Solution: llms-full.txt includes error handling patterns

### Verification Checklist

After AI generates Savvagent Flags integration code, verify:

- [ ] Correct package imported (`@savvagent/flags-sdk`, `@savvagent/flags-react`, etc.)
- [ ] API key loaded from environment variable (not hardcoded)
- [ ] API key uses correct prefix (`sdk_` for client-side, `srv_` for server-side)
- [ ] Provider wraps app at root level (React/Vue/Svelte)
- [ ] `user_id` or `anonymous_id` provided for sticky rollouts
- [ ] Default values specified for critical flags (graceful degradation)
- [ ] Error handling/fallbacks included (timeout, network errors)
- [ ] Cleanup called on unmount (if applicable)
- [ ] Single SDK instance created (not per-request)

## Keeping AI Context Updated

When Savvagent Flags releases new SDK versions:

1. We update `llms.txt` and `llms-full.txt` in this repository
2. AI assistants fetching from GitHub URLs get latest docs automatically
3. Local copies should be refreshed periodically
